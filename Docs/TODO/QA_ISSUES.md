# QA 이슈 로그

## 목적

이 문서는 QA 중 재현한 사용자 영향 결함을 기록하고, 수정 전후의 검증 근거를 남긴다. 장기 구조 개선·리팩터링 backlog는 [미해결 항목](UNRESOLVED_ITEMS.md)에서 관리한다.

## 기록 규칙

- MUST 재현 가능한 사용자 영향 문제만 이 문서에 기록한다.
- MUST 이슈마다 환경, 재현 단계, 기대 결과, 실제 결과, 검증 결과를 작성한다.
- MUST 로그·스크린샷에 access token, OAuth credential, 정확한 사용자 좌표, 개인 식별 정보를 남기지 않는다.
- MUST API 관련 이슈에 endpoint, method, HTTP/API error code를 기록하되 request·response 원문은 필요한 범위로만 안전하게 요약한다.
- MUST 수정 뒤 동일 환경과 가능한 다른 기기·OS 조합에서 재검증한다.
- SHOULD 동일 원인의 이슈는 가장 먼저 생성한 이슈에 연결하고 중복 항목을 만들지 않는다.
- SHOULD 구조적 원인이 반복되면 [미해결 항목](UNRESOLVED_ITEMS.md)의 P0~P2 항목에도 연결한다.

## 상태

| 상태 | 의미 |
| --- | --- |
| Open | 재현은 확인했지만 원인을 조사하지 않음 |
| Investigating | 원인 또는 영향 범위를 조사 중 |
| Fixed | 코드 수정은 완료했지만 검증이 남음 |
| Verified | 정의한 환경·시나리오에서 수정 확인 완료 |
| Won't Fix | 제품 결정으로 현재 수정하지 않음. 이유를 남김 |
